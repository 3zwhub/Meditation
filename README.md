# Meditation

우울과 불안을 **지속적으로** 개선하기 위한 도구를 만드는 프로젝트입니다.
인지행동치료(CBT), 수용전념치료(ACT), 변증법적 행동치료(DBT), 뇌과학(DMN, 편도체 등), 명상, 저널링, 자기확언을
따로 나열하지 않고, 각 기법이 겨냥하는 **메커니즘**을 기준으로 하나의 시스템으로 통합합니다.

> 이 도구는 전문 치료를 **대체하지 않는 보조 도구**입니다.
> 자살 생각이나 자해 충동이 들거나 일상생활이 어려울 만큼 힘들다면 바로 도움을 요청하세요.
> 자살예방상담전화 **109** · 정신건강위기상담 **1577-0199** · 응급 시 **119**

## 진행 방식

AI와 함께 다섯 단계로 만듭니다. 각 단계는 `prompts/` 폴더의 프롬프트 하나에 해당하고,
앞 단계의 결과물이 다음 단계의 입력이 됩니다.

```
1. 설계 → 2. 모듈 스크립트 → 3. 데이터·시스템 설계 → 4. 구현 → 5. 점검·개선
                                                      ↑              │
                                                      └──────────────┘
                                         (5단계에서 나온 작업을 4단계로 구현하며 반복)
```

| 단계 | 프롬프트 | 하는 일 | 입력 | 결과물 | 사용 도구 |
|---|---|---|---|---|---|
| 1 | [`01-foundation.md`](prompts/01-foundation.md) | 통합 프레임워크 설계 | 내 정보(어려움, 가용 시간, 치료 경험, 원하는 형태) | 메커니즘 지도, 상태별 라우팅, 루틴, 모듈 목록, 측정, 안전 장치, MVP 범위 | 대화형 AI |
| 2 | [`02-module-scripts.md`](prompts/02-module-scripts.md) | 모듈 스크립트 작성 | 1단계 결과물, 작성할 모듈 3~5개 | 바로 쓸 수 있는 명상·연습·저널링·확언 스크립트(형식 A~E) | 대화형 AI |
| 3 | [`03-data-structure.md`](prompts/03-data-structure.md) | 데이터 구조와 시스템 설계 | 1단계 결과물, 2단계 샘플, 구현 환경 | 데이터 모델, 추천·측정·안전 로직, 개인정보 보호, 화면 흐름, 구현 계획 | 대화형 AI |
| 4 | [`04-implementation.md`](prompts/04-implementation.md) | 구현 | `docs/`의 1~3단계 결과물, 이번 작업 1개 | 작동하는 코드, 테스트, 작업 완료 보고 | AI 코딩 도구(예: Claude Code) |
| 5 | [`05-review-and-improve.md`](prompts/05-review-and-improve.md) | 사용 점검과 개선 | 2주 이상의 사용 기록, 사용 점검표 | 안전 점검, 모듈별 효과 분석, 개선 계획(최대 3개), 다음 사이클 계획 | 대화형 AI |

## 단계별 사용법

### 1단계: 설계
1. `prompts/01-foundation.md`의 `[내 정보]` 칸을 채웁니다.
2. 구분선 아래 전체를 AI에게 붙여넣습니다. AI가 먼저 질문을 몇 개 하면 답합니다.
3. 결과물을 `docs/01-framework.md`로 저장합니다.

### 2단계: 모듈 스크립트
1. 1단계 결과물을 붙여넣고, 이번에 만들 모듈을 **3~5개만** 지정합니다.
2. 모든 모듈이 만들어질 때까지 반복합니다.
3. 결과물을 `docs/02-modules/`에 모듈별로 저장합니다.

### 3단계: 데이터·시스템 설계
1. 1단계 결과물 전체와 2단계 스크립트 2~3개를 붙여넣습니다.
2. `[구현 환경]`(산출물 형태, 사용자 범위, 기술 선호, 데이터 저장 방식)을 채웁니다.
3. 결과물을 `docs/03-design.md`로 저장합니다.

### 4단계: 구현
1. 1~3단계 결과물이 `docs/`에 있는지 확인합니다.
2. AI 코딩 도구에서 프롬프트를 붙여넣고, `[이번 작업]`에 구현 계획의 작업 하나를 적습니다.
   처음에는 "0. 프로젝트 초기 설정"부터 시작합니다.
3. 작업 하나가 끝날 때마다 완료 보고를 확인하고 다음 작업으로 넘어갑니다.
4. MVP가 완성되면 안전 시나리오를 점검하고 사용 점검표를 만듭니다.

### 5단계: 점검·개선
1. MVP를 **최소 2주** 사용한 뒤, 내보낸 기록과 사용 점검표를 넣습니다.
   저널 원문은 넣지 않아도 되고, 넣는다면 식별 정보를 지웁니다.
2. 나온 개선 작업을 4단계 프롬프트로 구현합니다. 설계 자체를 고쳐야 하면 해당 단계로 돌아갑니다.
3. 2~4주마다 반복합니다.

## 앱 실행하기

4단계 구현이 진행 중입니다. 지금은 **체크인 → 추천 → 연습 3개(생리적 한숨, 5-4-3-2-1 그라운딩, STOP)**와 위기 안내가 동작합니다.

필요한 것: Node.js 22 이상

```bash
npm install        # 처음 한 번
npm run dev        # 개발 서버 → 터미널에 나오는 주소(보통 http://localhost:5173)를 브라우저로 열기
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 (코드를 고치면 바로 반영) |
| `npm run build` | 타입 검사 → 배포용 빌드(`dist/`) → 외부 주소 검사 |
| `npm run preview` | 빌드 결과를 http://localhost:4173 에서 열기 (오프라인·설치 기능 확인용) |
| `npm test` | 로직·안전·콘텐츠·저장소 테스트 |
| `npm run e2e` | 실제 브라우저로 주요 흐름 테스트 |

휴대폰에 설치하는 방법(GitHub Pages 배포)은 구현 계획의 작업 15에서 추가합니다.

## 폴더 구조

```
prompts/        단계별 프롬프트 (1~5단계)
docs/           각 단계의 결과물
  01-framework.md   1단계: 통합 프레임워크
  02-modules/       2단계: 모듈 스크립트 (콘텐츠의 원본)
  03-design.md      3단계: 데이터·시스템 설계
  backlog.md        MVP 범위 밖 아이디어
content/        앱이 읽는 콘텐츠 JSON (docs/02-modules를 옮긴 것)
src/            앱 코드 (safety, domain, db, content, player, screens, ui)
tests/          단위·e2e 테스트
```

## 모든 단계에 공통된 원칙

- **안전 우선**: 위기 신호 감지와 안내는 다른 모든 기능보다 우선하며, 오프라인에서도 작동해야 합니다.
- **근거 기반**: 주장에는 근거를 붙이고, 확실하지 않은 정보는 확실하지 않다고 표시합니다. 뇌과학의 과장된 단순화를 피합니다.
- **최악의 날 기준**: 컨디션이 가장 나쁜 날에도 할 수 있는 최소 버전(2~5분)을 항상 둡니다.
- **자기비난 없는 설계**: 루틴이 끊겨도 죄책감을 주지 않고, 다시 시작하기 쉽게 만듭니다.
- **개인정보 보호**: 정신건강 기록은 매우 민감한 정보이므로, 저널 내용이나 점수를 외부로 보내지 않습니다.
- **조금씩 바꾸기**: 한 사이클에 바꾸는 것은 최대 3개로 제한해, 무엇이 효과였는지 알 수 있게 합니다.
- **이전 단계로 돌아가기**: 어느 단계에서든 앞 단계의 문제를 발견하면 "수정 제안"으로 따로 모아 반영합니다.
